Live updates

Screens normally ask the server every few seconds whether anything changed. With live updates the server tells them the moment it does, so stop prompts and alarms appear straight away and idle screens make far less database traffic. Each open screen then holds one of the web server's threads while it's connected (WEB_THREADS in .env, 12 by default): turn it on only with fewer screens than that, or raise WEB_THREADS first. Screens fall back to asking whenever the live connection drops.
