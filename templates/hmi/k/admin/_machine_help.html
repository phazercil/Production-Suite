Database table
The newest row (by the column you pick, usually a time stamp or an auto-number ID) is read each minute, through a read-only login. One table can hold every machine: pick the column that names the machine. If no new row arrives within the minutes you set, it counts as no data.
Read from URL
The URL returns JSON such as {"ppm":190,"count":48211,"recipe":"MG-24","run":1}. Field names can be paths like data.speed.
InfluxDB query
The newest values from the query; Flux results by _field, InfluxQL by column. {machine} is replaced with the machine's name. Readings older than 2½ minutes count as no data.
Pushed to server
POST http://<server>/api/feed/<machine> with {"ppm":190,"count":48211,"recipe":"MG-24","run":1} and header X-Feed-Key.
Filters cut
The machine's counter. The suite counts how much it went up each minute; a reset to zero is handled.
Errors and alarms
An error code (and message) in the reading, kept from when it appears until it clears; or the machine's alarm log table, one entry per new row. Pushed readings can send "error":"E214","errorText":"Film break".
Run signal
High/Low, 1/0, true/false, on/off or run/stop. Without one, the line counts as stopped at or below the stop speed (Admin › Rules).
No reading
After 2½ minutes without data, the screen shows an alarm and nothing is recorded, so a dropped feed never looks like downtime.
